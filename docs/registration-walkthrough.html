Enter backend API endpoint

3

Submit — API call and response

Clicking "Request booking" fires a POST /api/bookings with JSON payload.

The frontend sends a fetch POST with credentials: "include" so the session cookie is established. The backend validates the payload, generates a UUID booking ID, creates a 72-hour access token, and writes the record to SQLite.

POST https://nexetra-backend.fly.dev/api/bookings 
// Request body (application/json)
{
  "name":       "Alex Chen",
  "email":      "alex.chen@techcorp.io",
  "lab":        "Claude API in Action",
  "timezone":   "US Eastern",
  "slot":       "Slot B - 13:00 UTC",
  "goal":       "Evaluating Claude API integration patterns…",
  "sourcePage": "https://derricksobrien.github.io/free-lab-tour/?lab=anthropic"
}
201 Created
Response HTTP 201 — application/json 
// Success response
{
  "status":       "stored",
  "bookingId":    "BK-20260506-a3f7c2d1",
  "sessionId":    "f4a8c2e1b7d04e6a9c3f1d2e5b8a7c04",
  "accessToken":  "Rk9Yv2mXqzP8LdN3wJeA7bKcQs5uVfT",
  "accessPath":   "/api/access/Rk9Yv2mXqzP8LdN3wJeA7bKcQs5uVfT",
  "expiresAtUtc": "2026-05-09T13:00:00+00:00"   // 72 hours from booking
}
🔑
Token generation: accessToken is created with Python's secrets.token_urlsafe(24) — 32 URL-safe characters, cryptographically random. It expires 72 hours from booking time. The token is also indexed in SQLite for fast lookup.
🛡️
Error responses: missing/invalid fields return HTTP 422 with {"error": "Missing required field: email"}. Rate limiting on the access endpoint returns HTTP 429 after 20 requests per 60-second window per session.

5

Use the access token to load lab instructions

Student scrolls to the "Student access" section and clicks "Load my lab access".

The access form sends a GET /api/access/<token> request. The backend validates the token has not expired, looks up the matching lab in LAB_ACCESS_MAP, and returns lab-specific instructions, the GitHub repo URL, and the catalog path.

7

What is stored in the database

SQLite record written at booking time. No payment data, no secrets.

The bookings table in backend/bookings.db stores one row per registration. The access_token column is indexed for fast lookup on the access endpoint. The file is gitignored and never committed to source control.

Summary

Complete flow in one view

1 Student opens free-lab-tour/?lab=anthropic → lab dropdown pre-selected
2 Fills form with name, email, lab, timezone, slot, goal
3 POST /api/bookings → 201 → bookingId + accessToken

7 Full booking record stored in SQLite — token valid for 72 hours
